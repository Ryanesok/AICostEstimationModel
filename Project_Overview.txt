# OpenSpec: AI-Based Software Cost Estimator (Offline Desktop App)

## 1. Project Overview
Tujuan proyek ini adalah membangun sistem pendukung keputusan (Decision Support System) berbasis kecerdasan buatan untuk membantu manajer proyek memprediksi biaya dan estimasi waktu (*effort*) pengembangan perangkat lunak. Aplikasi harus berjalan 100% luring (*offline*) untuk menjaga privasi data finansial. 

## 2. Tech Stack
* **Language:** Python 3.10+
* **Machine Learning:** `scikit-learn`, `pandas`, `numpy` (Model: Support Vector Machine / Linear Regression)
* **GUI Framework:** `customtkinter` (CTk)
* **Model Serialization:** `joblib` atau `pickle`

## 3. Dataset Specification
* **Source:** PROMISE Software Engineering Repository (fokus pada dataset **COCOMO81** atau **Desharnais**).
* **Features (X):** Metrik proyek seperti *Lines of Code* (KLOC) atau *Function Points* (FP), beserta *effort multipliers* (jika menggunakan struktur COCOMO).
* **Target (y):** *Actual Effort* (Person-Months) atau *Actual Cost*.

## 4. Architecture & Core Components

Sistem ini dibagi menjadi dua skrip utama untuk memisahkan logika pelatihan dan antarmuka (separation of concerns):

### A. Model Pipeline (`model_pipeline.py`)
* **Tugas:** Memuat dataset CSV, melakukan pra-pemrosesan data (menangani *missing values*, normalisasi dengan `StandardScaler`), membagi data (Train/Test split).
* **Training:** Melatih dua model: `SVR` (Support Vector Regressor) dan `LinearRegression`.
* **Evaluation:** Mengembalikan metrik evaluasi akurasi, khususnya **MAE** (Mean Absolute Error) dan **R-Squared (R²)**.
* **Export:** Menyimpan model terlatih dan *scaler* ke dalam file `.pkl` agar bisa digunakan oleh GUI tanpa harus melatih ulang setiap aplikasi dibuka.

### B. Desktop GUI Application (`app.py`)
* **Tugas:** Memuat model `.pkl` dan menyediakan antarmuka interaktif bagi manajer proyek.
* **Form Input:** Sediakan *input fields* (Entry/Combobox) untuk memasukkan metrik proyek perangkat lunak (misalnya estimasi LOC, kompleksitas tim, dll).
* **Prediction Output:** Menampilkan hasil prediksi biaya/waktu secara instan setelah tombol "Estimasi" ditekan.
* **UI/UX Guidelines:** * Wajib menggunakan **dark theme** (tema gelap) atau warna *muted* (misalnya abu-abu tua `gray17` pada CustomTkinter). Antarmuka harus nyaman dan tidak menyilaukan mata untuk sesi analisis yang panjang.
    * Tata letak harus bersih, terstruktur rapi menggunakan `CTkFrame`, dan menggunakan sistem *grid* atau *pack* yang responsif.
    * Terapkan logika yang tidak merusak (*non-destructive*): pengguna harus bisa menghapus atau mengedit *input* dengan mudah (tombol "Reset Form") tanpa harus memulai ulang aplikasi.

## 5. Execution Steps for Claude Code
Tolong implementasikan spesifikasi di atas dengan urutan berikut:
1.  Buatkan struktur folder proyek dan file `requirements.txt`.
2.  Tuliskan kode untuk `model_pipeline.py` dengan fungsi yang *modular*. Tambahkan *dummy data* sementara (struktur COCOMO) di dalam skrip jika file CSV belum tersedia agar model bisa dites.
3.  Tuliskan kode untuk `app.py` menggunakan `customtkinter` yang memanggil model dari hasil `model_pipeline.py`.
4.  Pastikan kode dilengkapi dengan penanganan eror (*error handling*), misalnya jika pengguna memasukkan huruf pada *input* angka.
